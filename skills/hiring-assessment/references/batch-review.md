# Batch coverage and resumption

## Intake and stable references

List every supplied source, including unreadable and unopened inputs. Give each a stable source label such as S001; keep supplied filenames or document identifiers available for traceability. Count source versions separately from distinct people. Record the role brief/version and any selected playbook revision; reuse the same criteria across the batch.

Reuse existing candidate labels where identity is established. Otherwise use stable batch-local candidate labels or names appropriate to the user's output. Pseudonymous reporting is optional, not a prerequisite. If sources are confirmed versions for the same person, keep one candidate record with separate source coverage and claims. Similar names or overlapping employment alone do not justify merging people. Mark unresolved identity against source labels, ask only the necessary clarification and continue unrelated sources. Source labels can be assigned before identity is resolved.

For a later batch, continue the available register without renumbering earlier entries. If no prior register is accessible, use a clearly identified new batch namespace, or ask for the register if cross-batch continuity is required. Do not claim to remember assignments or block an independent new batch merely because old labels are unavailable.

## Source status and totals

Assign each source exactly one status:

- **Reviewed:** all relevant supplied content was read and its coverage checked.
- **Partially reviewed:** some content assessed, with outstanding pages/sections or unresolved limitations identified.
- **Blocked:** no substantive review possible; record the reason, including unresolved identity when that prevents attribution.
- **Pending:** not yet reviewed; this includes unopened sources, not known access failures.

Reconcile reviewed + partially reviewed + blocked + pending = supplied source count. Report distinct confirmed candidates separately and identify unresolved identities; do not add candidate counts or duplicate-version counts to the source total. A finished pass may include explicit partial or blocked sources, but no pending inputs. Label unfinished coverage **interim**; do not imply all evidence was reviewed merely because no work remains executable.

The batch overview indexes evidence and recommendations under the user's requested workflow. It must include sources without completed assessments and retain input order for traceability. Coverage states are not fit ratings. Do not prioritise candidates by document readability or evidence-label counts.

## Checkpoint when work is interrupted

Provide a compact checkpoint when stopping before completion or handing over a batch. Include the role brief/version, playbook revision if selected, source-to-candidate mapping or unresolved identities, each source's status and covered pages/sections, existing report references, current totals and the next pending action. Preserve labels, original observations and source-version conflicts on resumption.

Keep checkpoints in the conversation by default. Save them only when requested or when the user has already chosen a persistent assessment location; keep candidate records outside the shared skill and follow the chosen identity-handling preference. A checkpoint records progress, not the missing underlying evidence: reopen sources or reuse accessible reports before making substantive conclusions. If neither is available, report the limitation rather than reconstructing claims from memory.

If requirements change, record a new brief version and identify which reports use the old criteria. Apply the new version to requested work and offer to refresh affected earlier reports rather than silently rewriting them. Ask for confirmation only where the intended criteria or application are materially unclear.
